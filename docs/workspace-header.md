# Workspace header

The header uses one row for navigation, the current view, a shared search and download input, and display controls. Saved folders show `Workspace › Folder`, retaining the workspace icon. The workspace breadcrumb navigates up; the current folder is a label. Hover reveals the full breadcrumb. Collapsed or overlay navigation reserves 80px at the left for native macOS window controls. Docked navigation already reserves that space. Empty header areas and the current view label remain draggable.

Typing filters downloads by name or source URL in the active view. Navigation preserves the query, including when switching workspaces. A complete HTTP, HTTPS, or supported BTIH magnet link changes the leading search icon to a link and enables Download. Domains, filenames, incomplete links, and unsupported protocols remain search text. Typing and pasting never submit automatically.

The clear button appears only with text. Escape closes an open popover or dialog first; otherwise it clears the focused shared input. Cmd/Ctrl+F focuses the input. Cmd/Ctrl+N and New download menu actions focus and select its contents, closing overlay navigation when needed. The attached download options chevron opens type and video format choices, workspace default saving, and local torrent import, even with an empty input.

Issues #20 through #24 deliver the shared header, contextual destinations, submission feedback, download options, and responsive compression.

Compression follows the header's available width, so opening a docked inspector also compresses the controls. At 1100px or less, parent workspace text shortens first and Download uses its icon. At 1000px, destination text truncates while its button retains the full destination name and path in its tooltip. `Choose…` stays intact. At 900px, Sort/Group and List/Table combine into one icon button named View. Filter and More remain separate. The same display preferences drive both presentations; compact choices expose their selected state to assistive technology. Closing the popover restores focus to its trigger, and a focused layout toggle moves focus to View if resizing removes it. Widening an open compact menu closes it and restores focus to Sort/Group.

The inspector becomes a modal sheet at window widths of 1100px or less. Navigation follows at 900px or less, keeping its separate docked expansion preference. Sheets trap keyboard focus, close with Escape or outside interaction, and restore focus to the download or navigation trigger. Returning to a wide window docks the inspector with the same selection. Navigation closes when docking and stays closed on the next narrow resize. New download intentionally moves focus from navigation to the shared input.

`tests/ui/responsive-header.spec.ts` verifies each compression stage, compact layout/sort/group persistence, keyboard navigation, focus restoration, panel resizing, and accessibility of the compact menu and inspector sheet. A width sweep from 1600px through 720px checks long breadcrumbs and unresolved destinations, no header overflow, and at least 120px of typing space with a populated input. Browser tests use controlled Tauri IPC and the same WebKit engine family as the native shell.

The destination remains inside the input in empty, search, and link states. Workspace views use their default saved folder; saved-folder views use that folder. Aggregate views use the sole workspace's default folder, or show `Choose…` when multiple workspaces exist. Downloads settings can instead select an automatic workspace. If that workspace is unavailable, submission asks for a destination.

The destination popover groups saved folders by workspace and marks the current selection. Aggregate and cross-workspace selections show `Workspace › Folder`; hover reveals the full path. Add new location opens the native folder picker and adds the folder to the selected workspace, or to the recommended workspace when no destination is selected. It leaves the workspace default unchanged. Cancellation and errors preserve the draft and selection.

Temporary choices survive consecutive submissions and polling within the current view. Every sidebar or breadcrumb navigation resets them to the new view's natural default, while preserving the shared query. Download options opens with the selected destination's workspace and folder.

Submitting with `Choose…` opens a confirmation dialog with workspace and folder choices. Recommendations use the configured workspace when available, then the last successful destination in this app session, then the first workspace. Cancel and Escape retain the draft and restore input focus. The opt-in checkbox saves an automatic workspace through the existing atomic Rust preference store; failed saves keep the dialog open for retry. Automatic saving uses that workspace's default folder after navigation or restart. Settings → Downloads can switch between Ask each time and Use a default workspace. Older preferences default to prompting; workspace display settings remain independent.

`tests/ui/unified-header.spec.ts` covers the shared input, navigation, URL intent, Escape precedence, keyboard/menu focus, overlay navigation, and single-row layout with macOS insets. `tests/ui/destination.spec.ts` covers destination defaults, grouping, cross-workspace submissions, reset, confirmation, saved Settings, unavailable defaults, native picker cancellation/failure, retry, and accessibility. Rust preference tests reopen the actual file after changing the destination preference. Existing download and accessibility flows remain in `tests/ui/app.spec.ts`.

Enter and Download submit recognized links once while the request is pending. The Download button shows a spinner and exposes its busy state; typing remains available. A successful addition stays in the current view and clears the input only when it still exactly matches the submitted draft. Newer text, including a cleared input, survives completion. Failures show an error toast and preserve the draft and destination for retry.

Success toasts show the destination workspace icon, the download name from the library snapshot, and the workspace and saved folder. View opens the added download in the existing details inspector without changing the current view, query, or filters. Notifications use the IDs in the command receipt, including when the destination lies outside the active view. Navigating during submission keeps the progress indicator active, resets the new view's destination normally, and prevents a late response from restoring the previous view's override.

`tests/ui/submission.spec.ts` covers Enter/click, same-turn duplicate attempts, pending progress, preserved newer searches/links/clears, failure and corrected retry, aggregate confirmation, navigation during flight, workspace artwork, keyboard activation of View, in-place cross-workspace inspection, toast accessibility, and the 720px window. Browser interactions use controlled Tauri IPC; Rust command tests cover actual created-download receipts.
