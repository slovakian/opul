# Workspace header

The header uses one row for navigation, the current view, a shared search and download input, and display controls. Saved folders show `Workspace › Folder`. The workspace breadcrumb navigates up; the current folder is a label. Narrow headers shorten the identity and hide button text while keeping accessible names. Collapsed or overlay navigation reserves 80px at the left for native macOS window controls. Docked navigation already reserves that space. Empty header areas and the current view label remain draggable.

Typing filters downloads by name or source URL in the active view. Navigation preserves the query, including when switching workspaces. A complete HTTP, HTTPS, or supported BTIH magnet link changes the leading search icon to a link and enables Download. Domains, filenames, incomplete links, and unsupported protocols remain search text. Typing and pasting never submit automatically.

The clear button appears only with text. Escape closes an open popover or dialog first; otherwise it clears the focused shared input. Cmd/Ctrl+F focuses the input. Cmd/Ctrl+N and New download menu actions focus and select its contents, closing overlay navigation when needed. Download options still opens the existing import dialog for video, format, and local torrent choices.

Issue #20 delivers the shared header shell. Issue #21 adds contextual and cross-workspace destinations. Submission feedback and draft concurrency, split-button options, and the full stepped compression sequence remain in #22 through #24.

The destination remains inside the input in empty, search, and link states. Workspace views use their default saved folder; saved-folder views use that folder. Aggregate views use the sole workspace's default folder, or show `Choose…` when multiple workspaces exist. Downloads settings can instead select an automatic workspace. If that workspace is unavailable, submission asks for a destination.

The destination popover groups saved folders by workspace and marks the current selection. Aggregate and cross-workspace selections show `Workspace › Folder`; hover reveals the full path. Add new location opens the native folder picker and adds the folder to the selected workspace, or to the recommended workspace when no destination is selected. It leaves the workspace default unchanged. Cancellation and errors preserve the draft and selection.

Temporary choices survive consecutive submissions and polling within the current view. Every sidebar or breadcrumb navigation resets them to the new view's natural default, while preserving the shared query. Download options opens with the selected destination's workspace and folder.

Submitting with `Choose…` opens a confirmation dialog with workspace and folder choices. Recommendations use the configured workspace when available, then the last successful destination in this app session, then the first workspace. Cancel and Escape retain the draft and restore input focus. The opt-in checkbox saves an automatic workspace through the existing atomic Rust preference store; failed saves keep the dialog open for retry. Automatic saving uses that workspace's default folder after navigation or restart. Settings → Downloads can switch between Ask each time and Use a default workspace. Older preferences default to prompting; workspace display settings remain independent.

`tests/ui/unified-header.spec.ts` covers the shared input, navigation, URL intent, Escape precedence, keyboard/menu focus, overlay navigation, and single-row layout with macOS insets. `tests/ui/destination.spec.ts` covers destination defaults, grouping, cross-workspace submissions, reset, confirmation, saved Settings, unavailable defaults, native picker cancellation/failure, retry, and accessibility. Rust preference tests reopen the actual file after changing the destination preference. Existing download and accessibility flows remain in `tests/ui/app.spec.ts`.
