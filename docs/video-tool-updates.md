# Manual updates and runtime probation

Settings Check for updates resolves the signed runtime pointer and the newest yt-dlp release tag. It persists the last successful check and shows an available version with Update. Both actions use the immediate tools bridge. Ready, installed versions and the current invocation remain available while an update runs; its exclusive flag is the only extra status line. A metadata failure is silent. An installation failure records details in `Tools/updates.log`, retains the committed pair and shows the quiet failed flag. No scheduler is started by this ticket.

Setup and updates share signature, checksum, size, archive and health verification. If both components change, the runtime is verified and unpacked before the script is fetched. Every candidate script is tested against the installed runtime, including version, Python deprecation warnings, supported curl_cffi and QuickJS. A newer runtime is then tested with the intended script. An incompatible pair records a hold keyed by script version and the checked runtime number. The hold survives restart and avoids fetching that script again until the runtime pointer or script version advances. A second integrity failure persists a skip for that component version; newer releases remain eligible. Transient download and activation failures can retry through the next Update operation.

MediaEngine acquires a `VideoDownload` from the module when a managed video worker starts executing, after its concurrency wait. Acquisition captures the selected pair and counts activity under the same lock used for activation. Direct transfers and developer overrides do not count. Runtime unpacking and pair placement wait for no active managed video Downloads. Network preparation can continue, and further Downloads can use the current pair. After health checks, activation rechecks activity and the original selection, places complete version directories, then atomically commits state.json. Cancellation fences the job before aborting its task and never changes the installed selection. `VideoTools::cancel()` is shared by shutdown and the future Remove implementation. Remove must cancel first and stop and drain media users before deleting tool files.

The previous script is retained until another script update; runtime-only updates leave it alone. A runtime update retains the full last known working pair, even through subsequent script updates, until a video Download using the new runtime succeeds. MediaEngine reports success or failure when its process and readers finish. Cancellation and pause do not count as a failure. The first success clears runtime probation; a preceding failure atomically restores the retained pair. Existing users keep their captured paths until they drain, then unreferenced versions are pruned. Startup also restores the retained pair if the probationary runtime is missing or fails health validation. Ordinary rollback failures remain retryable, while integrity skips apply only to twice-rejected signed downloads. Startup prunes abandoned staging and version directories as before.
